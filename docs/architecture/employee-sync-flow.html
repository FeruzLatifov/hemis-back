Concurrency — peak time (semestr boshi)

Stsenariy Yuk Outbox Pattern javobi
50 OTM bir vaqtda sync qiladi 50 ta concurrent POST ✓ HikariCP pool (40 connection) + queue. p99 < 500ms.
Bulk import: 1 OTM × 5000 employee 5000 ta sequential POST (Univer queue) ✓ Univer queue 1 sec interval. ~1.5h to'liq sync. Sinxron OK.
Kafka cluster downtime Hech narsa publish bo'lmaydi ✓ outbox_event queue ortadi. Kafka qaytsa, OutboxPublisher catch up qiladi.
HEMIS-back deploy uzilishi 5xx qaytariladi ✓ Univer Yii queue retry qiladi (15s, exponential).
Multi-instance OutboxPublisher (3 pod) Race condition risk ✓ SELECT FOR UPDATE SKIP LOCKED — har pod o'z chunkini oladi.
Cache invalidator slow (Redis hiccup) Consumer lag ✓ Boshqa request'larga ta'sirsiz — alohida consumer thread pool.

6. Initial bulk sync vs steady state

🏗️ Initial Bulk Sync (one-time)

Maqsad: 224 OTM × ~100 employee = 22K row markazga ko'chirish.

  • URL: POST /api/v1/university/{code}/employees/sync-bulk
  • Chunk size: 500 employee/batch
  • Resume: synced_at cursor — yarim yo'lda fail bo'lsa, davom etadi
  • Kafka publish: YO'Q — past data, audit log etarli
  • Cache evict: YO'Q — initial sync paytida cache kerak emas
  • Davomiyligi: ~5-10 min/OTM (224 OTM × 10 min = qatla deploy)

🔄 Steady State Sync (continuous)

Maqsad: Univer'da har xodim yangilanganda real-time sync.

  • URL: POST /api/v1/university/{code}/employees/sync
  • Trigger: Yii afterSave hook → queue push → REST POST
  • Volume: ~224 update/day (avg)
  • Kafka publish: HA — cache invalidation, audit, search
  • Idempotent: SHA-256 hash compare — agar o'zgarmasa, SKIP
  • Latency: ~150ms (Univer perspektiva)

8. Eng muhim — 3 ta kafolat

✅ 1. Atomicity

DB write + outbox INSERT bitta transactionda. Hech qachon ajralmaydi.

@Transactional
public void upsert(...) {
  employeeRepo.save(employee);    // 1
  syncLogRepo.save(log);        // 2
  outboxAppender.append(...);  // 3
}  // COMMIT — uchchalasi birga yoki hech qaysi

✅ 2. Idempotency

Bir xil POST 100 marta kelsa ham — DB'da bitta row.

// Univer queue retry → bir xil payload yuboradi
var existing = repo.findByPinfl(pinfl);
if (existing.isPresent()
    && existing.get().contentHash().equals(hash)) {
  return;  // SKIP — no-op
}

✅ 3. Decoupling

Sync request backendning ichidan Kafka'ga ulanmaydi. Outbox table = buffer.

// Request thread:
save(employee) + save(outbox)  // 5ms
return 200 OK;

// Background (alohida thread):
@Scheduled
poll() { kafka.send(...); }
